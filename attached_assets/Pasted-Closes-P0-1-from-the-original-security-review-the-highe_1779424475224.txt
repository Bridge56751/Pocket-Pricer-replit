Closes P0-1 from the original security review — the highest-priority finding. Stops trusting the client-set X-Is-Pro header and verifies Pro entitlement via RevenueCat's REST API instead.

PR #2 (Group C Part A, the client release with Purchases.logIn(deviceId)) shipped ~2 weeks ago. Adoption is now high enough that flipping this on shouldn't brick existing Pro subscribers.

What ships in this PR

File	Change
NEW server/revenuecat.ts	Wraps RC REST API to look up device_id → returns whether 'Pocket Pricer Pro' entitlement is active. 5-min LRU cache. Fails closed on every error mode (timeout, 5xx, missing secret, network down) — never grants Pro on uncertainty.
server/routes.ts	New getIsPro(req) helper replaces 3 call sites that read req.headers['x-is-pro'] directly. Gated by VERIFY_PRO_VIA_RC env flag so deploying the code is a NO-OP until the flag is flipped.
.env.example	Documents the two new env vars (REVENUECAT_REST_SECRET, VERIFY_PRO_VIA_RC).
package.json + package-lock.json	Adds lru-cache as a direct dep (was transitive only).
5 files, +234 / -76. New file is 161 lines. server/routes.ts is +43 lines (the new helper + 3 one-line swaps). TypeScript: zero new errors.

Required pre-deploy setup

Before flipping the flag:

Add REVENUECAT_REST_SECRET to Replit Secrets. Get from RevenueCat dashboard → Project Settings → API keys → Secret keys. Starts with sk_. go here https://app.revenuecat.com/projects/e1533c84/api-keys
Verify alias coverage in RC dashboard — most active subscribers should now show both their anonymous ID ($RCAnonymousID:...) and their device_id (hw_...).
Deploy + rollout flow

Because of the feature flag, the deploy itself is risk-free:

Merge this PR → Replit autodeploys (or click Redeploy). Code is live but VERIFY_PRO_VIA_RC is unset → legacy header-trust path still in use, no behavioral change.
Smoke-test prod still works as before (existing Pro user opens app, Pro features work).
Add REVENUECAT_REST_SECRET to Replit Secrets (still no behavioral change since the flag is off).
Add VERIFY_PRO_VIA_RC=true to Replit Secrets + Redeploy → cutover to RC-verified path is live.
Watch logs for ~30 min. Look for [rc] lines. Spot-check a Pro user's experience.
If anything breaks → unset VERIFY_PRO_VIA_RC + Redeploy → instant rollback. No code revert needed.
Why the feature flag (vs. always-on)

This is the highest-risk PR in the entire roadmap. The 20% of users who haven't updated past app v1.5.2+ have no device_id alias in RevenueCat. If we cut over without a kill-switch and an unforeseen issue surfaces, Pro features break for paying subscribers. The flag lets us:

Deploy the code dark, then flip when ready
Roll back in 30 seconds if anything goes wrong
Iterate on the implementation without re-deploying for code-only changes
What this PR does NOT close

device_id spoofing — an attacker who somehow obtains a real Pro user's device_id (e.g. via friend-sharing) can still impersonate them by sending that device_id in the X-Device-Id header. The proper fix is JWT auth (SECURITY_REVIEW.md P0-2), queued for a later phase. This PR specifically closes the X-Is-Pro header spoofing loophole.
